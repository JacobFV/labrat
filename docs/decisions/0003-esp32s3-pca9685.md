# ADR-0003: ESP32-S3 microcontroller with a PCA9685 PWM driver

* Status: Accepted
* Date: 2026-10-11

## Context

The body needs to generate 8 (up to 16) servo PWM signals, run 100 Hz minimum-jerk interpolation
with IK per tick, enforce safety (limits, watchdog, brownout), and talk to the Android head over
USB **as the USB host** (see [ADR-0004](0004-usb-aoa-link.md)).

## Decision

* **ESP32-S3** (DevKitC-1 in v0, WROOM-1 module on the v1 PCB): it has native USB OTG with host
  mode (GPIO19/20), dual core, FPU for IK, and Wi-Fi/BLE as a spare transport. It costs ~$3.10 as
  a module.
* **PCA9685** over I²C (0x40) for servo PWM, with OE on GPIO10 for a hardware "relax all" line.

## Alternatives considered

* **ESP32-S3 LEDC PWM directly:** cheaper by ~$0.90 and higher resolution (14-bit), but uses 8+
  GPIOs, and pulse timing becomes firmware-dependent. Kept on the roadmap as the fix for the
  ±0.22° quantization floor.
* **RP2040:** USB host is possible only via PIO and is less mature, and there's no radio.
* **STM32 with USB OTG:** fine technically, but a smaller hobbyist ecosystem and no Wi-Fi.
* **Original ESP32:** no native USB, so no AOA host.

## Consequences

* PCA9685 resolution is 4.88 µs/count ≈ 0.44° per count, which means **±0.22° quantization on every
  joint**. This is a fixed term in the error budget ([kinematics.md §4](../kinematics.md#4-command-resolution-pca9685)).
* The OE pin gives a single-line, firmware-independent way to make every servo go limp.
* 8 spare PWM channels are available for accessories.
