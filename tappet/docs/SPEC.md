# Tappet — System Specification (source of truth)

Tappet is a ~$99 desktop robot. A user-supplied **Android phone is the head** (display, camera,
mic, speaker, compute, networking) on a 2-axis neck. Two light **3-DOF arms with capacitive stylus
tips** operate a second phone (typically an iPhone) lying in a tray in front of the robot. An
**ESP32-S3** drives eight servos through a **PCA9685**. The robot is powered from a USB-C wall
charger and **charges and talks to the Android head over USB** (Android Open Accessory).

All numeric geometry, joint maps and pins live in [`config/robot.json`](../config/robot.json).
Every component (firmware defaults, Python tools, Android app, CAD) must agree with it; tests check this.

---

## 1. System architecture

```
 USB-C PD charger (>=20 W, 9 V)
        │
 ┌──────▼──────────────────────────── Tappet body ───────────────────────────────┐
 │ CH224K PD trigger (9 V) ─ PTC 3 A ─┬─ Buck A 5 V/5 A ── V+ servo rail (1000 µF) │
 │                                    └─ Buck B 5 V/3 A ── 5V logic ──┬─ ESP32-S3 │
 │                                                                     └─ USB pwr sw (1.5 A) ─ VBUS ─┐
 │ ESP32-S3  GPIO19/20 (USB OTG, HOST) ───────── D-/D+ ──────────────────── USB-C "HEAD" port ──────┤
 │ ESP32-S3  GPIO8/9 (I²C) ── PCA9685 ── ch0..7 ── 8 servos                                          │
 └──────────────────────────────────────────────────────────────────────────────────────────────────┘
                                                                                  │ USB-C cable
                                                                          Android head (accessory mode)
                                                                           ├─ Wi-Fi: web UI on :8080 ──► iPhone / laptop browser
                                                                           └─ Claude API (agent)
```

* The ESP32-S3 is a **USB host** on its native OTG port and puts the Android phone into
  **AOA accessory mode**. The phone is charged (VBUS 5 V, 1.5 A advertised via 22 kΩ Rp on CC) while
  the app streams JSON lines over bulk endpoints. No OTG adapter, no battery drain.
* The DevKit's second USB port (UART bridge) exposes the **same protocol at 115200 baud** for a PC
  (Python tools, simulator parity, flashing).
* The Android app can alternatively talk over **USB-serial** (phone as host with an OTG cable into
  the UART port) or **TCP** (to the Python simulator, port 7777) — useful for development.
* The iPhone (or any browser) connects to the **Android head's web UI** (`http://<head-ip>:8080`),
  pairing with a 6-digit PIN shown on the face. The same web UI is served by the Python bridge on a PC.

## 2. Servo / joint map

| ch | joint | meaning | gear | notes |
|----|-------|---------|------|-------|
| 0 | L_YAW | left arm heading ψ | 1.5 (20T servo → 30T turret) | positional SG90 |
| 1 | L_SHOULDER | θ1 upper-arm elevation | 1 | MG90S recommended |
| 2 | L_ELBOW | θ2 absolute forearm angle | 1 | MG90S, via parallel linkage |
| 3 | R_YAW | right arm heading ψ | 1.5 | |
| 4 | R_SHOULDER | θ1 | 1 | mirrored (dir −1) |
| 5 | R_ELBOW | θ2 | 1 | mirrored (dir −1) |
| 6 | NECK_PAN | head pan | 1 | |
| 7 | NECK_TILT | head tilt (neg = look down) | 1 | |
| 8–15 | spare | | | broken out on PCA9685 header |

`pulse_us = 500 + s * 2000/180`, `s = s_zero + dir * gear * (q - neutral)`, `s` clamped to [0,180],
`q` clamped to [min,max]. `s_zero` is the per-unit trim found during calibration and persisted in NVS.

**Why positional, not continuous-rotation servos:** continuous servos only control speed; without
encoders the stylus position drifts and cannot be repeated to the ~2 mm an iPhone needs. Positional
servos + calibration + light gearing on yaw is the cheapest path to repeatable taps.

## 3. Arm kinematics (identical in firmware C++, Python, Kotlin)

Per arm parameters (robot.json `arms.<A>`): base `(bx,by)` on the desk, shoulder height `H`,
shoulder radial offset `r0`, link lengths `L1`, `L2`, tool offset `tool_dx` (radial, forward) and
`tool_dz` (down) from the forearm tip (wrist pivot) to the stylus tip.

**FK** (ψ, θ1, θ2 in degrees):
```
r = r0 + L1 cos θ1 + L2 cos θ2 + tool_dx
z = H + L1 sin θ1 + L2 sin θ2 - tool_dz
x = bx - r sin ψ
y = by + r cos ψ
```
**IK** (x,y,z) → (ψ,θ1,θ2), elbow-up solution:
```
dx = x - bx ; dy = y - by
ψ  = atan2(-dx, dy)
r  = hypot(dx,dy) - r0 - tool_dx
zp = z - H + tool_dz
D  = hypot(r, zp)                      require |L1-L2| <= D <= L1+L2  else "unreachable"
φ  = atan2(zp, r)
α  = acos((L1² + D² - L2²) / (2 L1 D))
β  = acos((L2² + D² - L1²) / (2 L2 D))
θ1 = φ + α
θ2 = φ - β
```
Then check joint limits and `linkage.rel_min <= θ1-θ2 <= linkage.rel_max`, else error `limit`.
Shared test vectors live in `config/kinematics_vectors.json` (generated by the Python package,
consumed by firmware native tests and Android unit tests).

## 4. Body protocol (ESP32 ⇄ host) — v1

Newline-delimited JSON (UTF-8, one object per line, ≤ 2048 bytes). Same bytes over UART, AOA
bulk endpoints and simulator TCP.

* Request: `{"id": <uint>, "cmd": "<name>", ...args}`
* Response: `{"id": <id>, "ok": true, ...}` or `{"id": <id>, "ok": false, "err": "<code>", "msg": "..."}`
* Event (unsolicited): `{"evt": "<name>", ...}`

Motion commands (`joints`, `move`, `tap`, `swipe`, `neck`, `home`, `park`) are **queued** (depth 16);
the response is sent immediately with `"queued": true`, and an event `{"evt":"done","id":<id>}` is
emitted when that motion finishes (or `{"evt":"error","id":<id>,"err":...}` if it fails at run time).
Motion uses minimum-jerk interpolation at 100 Hz; `ms` defaults are computed from `max_vel` if
omitted. Cartesian moves (`move`, swipe stroke) interpolate in Cartesian space with IK per tick.

| cmd | args | response extras |
|-----|------|-----------------|
| `hello` | – | `fw:"tappet-fw", ver, proto:1, servos:8, uptime_ms` |
| `ping` | – | `t` (ms). Also feeds the watchdog. |
| `enable` | – | energizes servos (PCA OE low) holding current targets |
| `relax` | – | OE high: servos limp, queue cleared |
| `stop` | – | clears queue, holds current position |
| `status` | – | `enabled, busy, queue, joints:{NAME:deg}, tools:{L:[x,y,z],R:[x,y,z]}, vservo, vin, faults:[]` |
| `joints` | `q:{NAME:deg,...}, ms?` | queued |
| `move` | `arm:"L"|"R", x, y, z, ms?` | queued; `unreachable`/`limit` checked at enqueue |
| `tap` | `arm?:"L"|"R"|"auto", x, y, z, hold_ms?=60, press_mm?=2.5, approach_mm?=8, ms?` | queued; `arm` resolved |
| `swipe` | `arm?, x0,y0,x1,y1, z, ms?=400, press_mm?, approach_mm?` | queued; `arm` resolved |
| `neck` | `pan?, tilt?, ms?` | queued |
| `home` | `ms?` | queued (all joints to `home`) |
| `park` | `arm?:"L"|"R"|"both"` | queued |
| `servo_raw` | `ch, us` | immediate, requires enabled; for calibration |
| `calib_get` | – | `joints:{NAME:{ch,gear,dir,s_zero,neutral,min,max,home,park,max_vel}}` |
| `calib_set` | `joints:{NAME:{field:value}}, save?:bool` | persisted to NVS when save |
| `geom_get` | – | `arms:{L:{...},R:{...}}, linkage:{rel_min,rel_max}` |
| `geom_set` | `arms?, linkage?, save?` | |
| `reset_calib` | – | restore compiled defaults (and erase NVS) |
| `fk` | `arm` | `x,y,z` |
| `ik` | `arm, x,y,z` | `q:{YAW,SHOULDER,ELBOW}` or error |
| `watchdog` | `ms` (0 = off) | |
| `stream` | `hz` (0 = off, max 20) | periodic `{"evt":"status",...}` |
| `phone_power` | `on:bool` | toggles head VBUS (forces re-enumeration) |

`tap` sequence: (if needed) lift current arm to `z+approach_mm` → move above `(x,y)` →
descend to `z - press_mm` (the compliant stylus absorbs the overtravel) → hold → rise to
`z+approach_mm`. `auto` arm = the arm on the same side as `x` (x<0 → L, else R), falling back to
the other arm if unreachable. Before an arm works over the screen, the **other** arm is parked if
its tool is within 60 mm (xy) of the target.

Motion commands require `enable` first (`not_enabled`). `stop`, `relax` and the watchdog cancel running/queued motions, each reported as `{"evt":"error","id":N,"err":"fault","msg":"cancelled (...)"}`. `joints` clamps targets to joint limits but rejects linkage violations with `limit`. Default `ms` when omitted = max(60, 1.875·|Δq|max/max_vel·1000); Cartesian speed ≤ 150 mm/s.

Neck: positive pan turns the head CCW seen from above (toward the robot's left, −x), matching the yaw convention; negative tilt looks down.

Errors: `bad_json, unknown_cmd, bad_args, unreachable, limit, not_enabled, queue_full, fault`.

Events: `boot{fw,ver}`, `done{id}`, `error{id?,err,msg}`, `status{...}`, `button{action:"short"|"long"}`,
`fault{code}`, `watchdog{}`.

Safety: if enabled and no command for `watchdog_ms` (default 5000) → park both arms, then relax and
emit `watchdog`. The BOOT button: short press = toggle enable/relax, long press (>1.5 s) = home.
Servo rail < 4.3 V → `fault{code:"brownout"}`, motion paused.

## 5. AOA (Android Open Accessory) handshake (firmware ↔ Android)

1. ESP32 USB host enumerates the device. If VID 0x18D1 and PID 0x2D00/0x2D01 → already accessory.
2. Else control IN `GET_PROTOCOL` (bRequest 51, type 0xC0) → protocol ≥ 1.
3. Control OUT `SEND_STRING` (52, type 0x40, wIndex 0..5): manufacturer, model, description,
   version, uri, serial (from `robot.json.link.aoa`).
4. Control OUT `START` (53). The phone re-enumerates as an accessory.
5. Claim interface 0, find bulk IN/OUT; stream protocol bytes.

Android declares `res/xml/accessory_filter.xml` with manufacturer `Tappet`, model `TappetBody`, so
the app auto-launches when the head is docked.

## 6. Head web API (Android app; mirrored by the Python bridge)

Base `http://<head>:8080`. All `/api/*` except `/api/pair` require header `X-Tappet-Token: <token>`
(or `?token=`). Static UI from `web/` (remote control + `touchpad.html`).

| method | path | body / query | result |
|--------|------|--------------|--------|
| POST | `/api/pair` | `{pin}` | `{token}` |
| GET | `/api/status` | | `{link, body:{status}, calib, agent:{busy}}` |
| POST | `/api/cmd` | raw body-protocol request (without id) | body response |
| POST | `/api/tap` | `{u,v, arm?, hold_ms?}` (screen-normalized 0..1, u→right, v→down) | ok |
| POST | `/api/swipe` | `{u0,v0,u1,v1, ms?, arm?}` | ok |
| POST | `/api/type` | `{text}` | ok |
| POST | `/api/neck` | `{pan, tilt}` | ok |
| POST | `/api/jog` | `{arm, dx,dy,dz}` (mm) | `{x,y,z}` |
| GET | `/api/camera.jpg` | `?rectified=1` | JPEG |
| POST | `/api/say` | `{text}` | ok |
| POST | `/api/chat` | `{text}` | `{reply}` (agent) |
| GET/POST | `/api/calibration` | screen calibration JSON | |
| POST | `/api/calibrate/auto` | `{arm?}` | runs touch-probe calibration |
| POST | `/api/touchpad/event` | `{x,y,w,h,t}` from touchpad page (no token; same LAN) | ok |

| POST | `/api/taptest` | `{n:100}` | `{results}` |

### Screen calibration

Maps target-screen normalized coordinates `(u,v)` (u = 0 left → 1 right, v = 0 top → 1 bottom,
as seen by a person using the phone) to world `(x,y)` mm with a **homography** `H_sw` (3×3), plus
`surface_z`. Default from tray geometry + device profile; refined by **touch-probe auto-calibration**:
the target phone opens `touchpad.html` full-screen, the robot taps a 3×3 grid of world points, the
page reports where touches registered, and a least-squares homography is fitted (DLT). A second
homography `H_ic` maps head-camera pixels at the `look_at_tray` pose to `(u,v)` (user clicks the four
screen corners in a snapshot) so the agent sees a rectified screen image.

## 7. Agent (Android head)

Claude Messages API with tools: `tap(u,v)`, `double_tap`, `long_press`, `swipe(u0,v0,u1,v1)`,
`type_text(text)`, `look_at_device()` (returns rectified screen image), `look_at_user()`,
`move_head(pan,tilt)`, `set_timer(seconds,label)`, `add_reminder(when_iso,text)`, `add_task`,
`list_tasks`, `complete_task`, `remember(fact)`, `recall(query)`, `get_time`. Final text replies are
spoken with TTS. API key in app settings. Default model `claude-sonnet-5`.
